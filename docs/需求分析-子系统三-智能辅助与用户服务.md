# 软件工程课程需求分析文档（子系统三）

## 智能辅助与多角色用户服务子系统（DeepSeek）

---

### 1. 文档说明

| 项目 | 内容 |

| 子系统名称 | 智能辅助与多角色用户服务子系统 |

---

### 2. 引言与编写目的

本平台用户涵盖**不同学校的学生与教师**，角色差异导致对系统的熟悉程度与目标差异显著：新生可能不了解如何切换校区上下文、如何区分「上课占场」与「课外预约」；教师更关注班级活动场地与冲突处理。仅靠静态帮助文档难以覆盖长尾问题。本子系统通过**搭载 DeepSeek 等大模型能力**，提供对话式引导、步骤拆解与上下文相关问答，帮助**新手快速上手**。本文档界定智能服务的业务目标、与业务数据的结合方式、安全与合规要求，以及与子系统一、子系统二的协作边界。

---

### 3. 技术参考（检索摘要）

DeepSeek 开放平台提供与常见 OpenAI 兼容风格的 **HTTP API**，典型能力包括：**对话补全**（`chat/completions`）、**流式输出**（`stream`）、**JSON 模式**（结构化输出）、以及 **`tools` 函数调用**（由模型决定是否调用后端函数以查询实时数据）。官方文档见：[DeepSeek API 文档](https://api-docs.deepseek.com/zh-cn/)、[创建对话补全](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。本课程项目在需求层面要求：**API Key 仅驻留服务端**，通过学校 API 网关或密钥托管下发，**禁止前端直连携带密钥**。

---

### 4. 系统目标与范围

**4.1 目标**

- **新手 onboarding**：首次登录简短引导（可跳过）；自然语言提问如「今晚想打篮球，怎么约最近的场？」结合 `school_id`、角色、定位授权状态给出**分步指引**与**深链跳转**。
- **功能解释与排错**：说明提前预约、取消政策、提醒设置、评论与报修入口；对无空闲、权限不足等错误给出可读原因与下一步。
- **受控回答（防幻觉）**：优先通过**函数调用**拉取子系统一、二的结构化结果（空闲片段、是否自带器材、清洁摘要等），再组织自然语言；数据不可用时应明确提示刷新或联系管理员，**禁止编造预约号或场次**。
- **多校多角色上下文**：会话绑定租户与角色，各校开放时间、审批规则等通过**配置表 + 系统提示**注入，避免「一刀切」话术。

**4.2 范围（In Scope）**

对话界面（Web 或 App 内嵌）、快捷问题、会话历史（可选，需保留期限与脱敏策略）；服务端 DeepSeek 代理、提示词模板版本管理、流式与超时；**工具函数清单**与子系统一、二只读（或受限）接口对齐。

**4.3 范围外**

创建预约、取消预约、发表评论等**写操作**仍由用户在前端或各子系统接口完成；助手仅可**跳转页面**或**返回已格式化的表单草稿**（若业务允许），最终提交须经用户确认与服务器权限校验。

---

### 5. 用户与干系人

- **学生**：快速学会课外预约、理解推荐与提醒、查询器材与清洁概况。
- **教师**：查询与课程相关的场地说明、反馈场地问题入口。
- **信息化部门**：认证、网关、密钥与日志留存策略。
- **法务与学工**：生成式 AI 使用告知、未成年人与内容合规（若适用）。

---

### 6. 功能性需求

**FR-A1 对话式帮助**  
多轮对话与澄清（如先问运动类型再缩小场地类型）；回答语言与术语贴近校园场景。

**FR-A2 场景化入口**  
首页或悬浮「问一问」；预设问题如「如何取消预约？」「空闲时段是什么意思？」。

**FR-A3 DeepSeek 集成**  
后端代理请求；模型参数（如 `temperature`、`max_tokens`）可配置；支持流式返回改善体验。

**FR-A4 工具与函数调用**  
标准函数示例（名称可在详细设计中固化）：`get_user_reservations`、`search_venue_availability`、`get_venue_detail`（含器材、清洁、负责人摘要）、`get_school_booking_policy`（读配置）。模型仅在**当前用户 OAuth 上下文**下调用，**禁止跨用户查询**。

**FR-A5 权限与隐私**  
不得泄露他人预约详情、联系方式；会话 ID 与用户 ID 绑定；上下文定期过期；日志脱敏。

**FR-A6 输出内容安全**  
关键词与策略过滤；违法、违规、作弊类请求拒绝并记录；对医疗、法律等高风险领域提示「非专业建议」。

**FR-A7 降级与人工入口**  
模型或网络不可用时切换静态 FAQ 与体育部电话等可配置入口。

**FR-A8 可观测与成本**  
按租户统计调用量、Token、失败率；日限额与限流防刷；用户可对回答点赞或点踩用于运营优化（可选）。

**FR-A9 提示词与知识版本**  
系统提示与学校政策变更可版本化发布与回滚；重大变更留审计记录。

---

### 7. 非功能性需求

- **延迟**：首 token 时间满足交互可接受范围（具体指标在设计与压测中量化）。
- **可靠性**：超时重试策略不导致重复写业务（因本模块默认只读工具）；熔断时快速降级 FAQ。
- **合规**：训练数据不默认使用本校师生对话作为模型微调素材（除非单独签署协议）；满足数据出境与采购要求，必要时采用合规替代模型（需求层标注为约束）。

---

### 8. 与其他子系统的协作

- **子系统一**：提供预约列表、空闲查询、规则说明接口；助手引导用户完成 UI 操作，**最终确认预约以子系统一事务为准**。
- **子系统二**：提供清洁状态、用具自带策略、负责人摘要；助手回答「要不要带球拍」「今天扫没扫」等问题时**以结构化字段为准**，不凭想象作答。

---

### 9. 假设与约束

- DeepSeek 或备选服务可用且合同与数据路径符合学校规定。
- 大模型可能产生不准确表述，**支付、签约、最终预约确认**必须用户显式点击且服务端强校验。

---

### 10. 验收要点（摘要）

测试账号在约 5 分钟内借助助手完成一次课外预约路径演练；关于空闲、自带器材的回答与数据库一致；API Key 不暴露于浏览器；滥用与异常流量被限流；降级 FAQ 可访问。

---

### 11. 测试需求要点（摘要）

模拟无工具、工具超时、工具返回空、恶意跨用户提问等场景；抽检回答是否含虚构预约号；验证流式中断后前端状态；验证不同租户政策注入后话术差异。

---

### 12. 风险与对策

模型幻觉：**强制工具优先**于自由叙述关键事实；权限误配：**网关与函数侧双重鉴权**；成本失控：**按租户配额与告警**。

---

### 13. 会话留存、审计与可解释性

对话日志用于排错与合规审计时，应**脱敏**（隐去身份证号、完整学号等，规则由学校定）；留存周期可配置，到期自动删除或匿名化聚合。面向用户可提供「本次回答依据了哪些查询结果」的**简要来源说明**（如「已查询您未来 7 天内的预约列表」），增强信任；**不展示**其他用户或内部主键等敏感细节。

---

### 14. 可选增强：政策文档检索（RAG）

若学校提供《场馆开放办法》《收费细则》等**已审核 PDF 或网页**，可在二期引入检索增强生成（RAG）：助手回答政策类问题时先检索片段再生成，片段来源向用户展示标题与章节；**RAG 库更新**须与法务确认，避免过期条款误导。本期可仅采用结构化配置表 + 工具调用，不强制 RAG。

---

### 15. 与无障碍及国际化的关系

界面层应保证键盘可达与读屏友好（需求可引用 WCAG 2.1 AA 作为目标）；多语言（中/英）场景下，助手 `locale` 与 UI 语言一致，**业务数据**（场地名）仍以学校主数据为准不自动翻译，除非学校提供官方译名表。
