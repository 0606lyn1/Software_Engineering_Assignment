# 实验报告四：静态建模实践

**实验名称：** 实验四 静态建模实践

**子系统：** 子系统一——多校体育场地预约与时空调度子系统

**对应代码：** `com.example.tiyu` 包下预约相关类

---

## 报告说明

本报告对子系统一进行 UML 静态建模，类图、包图、构件图均对照 `stadium` 后端实际源码结构绘制。对象图以种子数据"zhangsan 预约羽毛球1号馆"为场景实例化。

## 一. 实验目的

1. 掌握类图绘制，定义类的属性、方法及类间关系。
2. 掌握对象图绘制，展示运行时对象实例快照。
3. 掌握包图、构件图、部署图，描述代码组织与物理架构。
4. 使静态模型与 `Reservation.java`、`ReservationServiceImpl.java` 等源码一致。

## 二. 实验内容

绘制类图、对象图、包图、构件图、部署图五种静态视图，覆盖子系统一核心类及其与子系统二的依赖关系。

## 三. 实验步骤和结果

### 1. 类图设计

#### 1.1 核心类（来自源码）

| 类别 | 类名 | 职责 | 文件路径 |
| --- | --- | --- | --- |
| 控制层 | ReservationController | 预约 REST 端点 | controller/ReservationController.java |
| 控制层 | VenueController | 场馆 REST 端点 | controller/VenueController.java |
| 服务接口 | ReservationService | 预约业务接口 | service/ReservationService.java |

| 实体 | Venue | 映射 t_venue | entity/Venue.java |

| DTO | ReservationCreateRequest | 创建请求参数 | dto/ReservationCreateRequest.java |

| 属性 | 类型 | 数据库列 |
| --- | --- | --- |

### 4. 构件图

| 构件 | 类型 | 接口 | 说明 |
| --- | --- | --- | --- |
| WebApp (first) | 前端 SPA | HTTP/JSON | Vue 3 应用，代理 /api → :8080 |
| API Server (stadium) | Spring Boot | REST /api/* | 端口 8080 |
| ReservationAPI | 后端子构件 | POST/GET/DELETE /api/reservations | ReservationController |
| VenueOpsAPI | 后端子构件（子系统二） | GET /api/venue-ops/{id}/availability | 可约性查询 |
| MySQL (tiyu) | 数据库 | JDBC | t_reservation, t_venue, t_user |

**构件依赖：** WebApp → ReservationAPI；ReservationAPI → VenueOpsAPI（同步调用）；ReservationAPI → MySQL

![](./静态建模-构件图.svg)

### 5. 部署图

| 节点 | 部署内容 | 说明 |
| --- | --- | --- |
| 客户端浏览器 | Vue 3 SPA（静态资源） | 用户通过浏览器访问 |
| 应用服务器 | Spring Boot JAR（stadium） | 单体部署，含子系统一/二/三 |
| 数据库服务器 | MySQL 8.4（tiyu 库） | 存储全部业务表 |

**通信：** 浏览器 HTTPS/HTTP → Nginx（可选）→ Spring Boot :8080 → MySQL :3306

**当前部署特点：** 单库单应用，无多校租户物理隔离。

## 四. 实验总结

### 实验中遇到的问题

原类图包含 TeachingOccupancy、LockRecord、RecommendationService 等未实现类，对象图使用了不存在的 tenant_id 字段。

### 解决方法

以 `entity/` 目录下实际 Java 类和 `db.sql` 表定义为唯一依据重建静态模型。

### 思考与收获

静态建模的核心价值是建立"需求→代码→数据库"三方一致的骨架。通过对象图实例化种子数据场景，验证了类图关联关系在运行时的正确性。
